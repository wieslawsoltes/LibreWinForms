# Explicit SDK startup for native modal sessions

The actual source-first/package SDK module initializer now recognizes
`--libre-native-modal-sessions` before registering the canonical backend. Its
immutable typed `ProGpuStartupOptions` selects the existing explicit
`ProGpuPlatform.Register(enableNativeModalSessions: true)` path. With no request,
the unchanged parameterless registration keeps the default off.

Pass the argument to the built Forms application during final qualified macOS
acceptance. The SDK observer and ordinary source-first applications consume the
same generated initializer; no custom replacement service or source edit is
needed. The owned Cocoa factory, hidden owner binding, exact attached input
context, original point/line scrolling and creating-thread native retirement
continue to validate every actual popup. Source `ShowDialog` owns Begin/release
and restores its retained source disable/focus frame only after native completion.

Unknown native-modal options and duplicates reject. Windows/Linux explicitly
reject the Cocoa request instead of silently choosing another session policy.
Arguments after `--` remain application data, and all arguments are passed to
the application unchanged. Parsing produces an immutable value before registration;
later changes to caller argument storage cannot change a running source service.

Authored controls cover those boundaries, actual service construction and the
real generated SDK initializer's ordering/default branch. None were executed.
No build, test, verifier, CI, native/UI/VM execution or runtime staging was done;
the exact qualified ProGPU pin is unchanged. This is a child of #150, not a new
default or complete application qualification. Final validation must use the
qualified producer/source/package union and exercise real modal dialogs, nested
menus/dropdowns/tooltips, precise input, focus restoration and deferred teardown.
